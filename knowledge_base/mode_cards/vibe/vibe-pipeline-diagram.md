## 意图

把一条流程画成"谁在哪一步卡住"的管理图时选它：规定单向流向、工序节点、瓶颈高亮、资源对齐四组设计要求。与"逻辑关系图设计"的本质差别：带时序的单向工序流（可标注时长/资源），不是概念关系网。

## 核心手法

1. modes_design._build_pipeline_diagram_prompt：流程方向左→右或上→下单向，无回路（循环流程除外）。
2. 工序节点=方框+工序名+时长/资源，节点间距均匀；箭头=流向，实线主流程、虚线支线/反馈。
3. 瓶颈工序高亮（色/形），关键路径标红。
4. 资源标注人/机/料/时，工序下方对齐；适配器传 style=扁平矢量、工序槽=场景解析首个人物或物件（空则"工序待定"）、count=4。

## 参数表

| 参数 | 典型值 | 越界后果 |
|---|---|---|
| 核心数据包 | 含 _视觉调性/_场景描述 的 JSON | 空包时色彩基调落"高对比"、工序行落"工序待定" |
| 工序来源 | 场景文本 | 未在场景中写明的工序不会出现在图内 |
| 数量 count | 4（适配器硬编码） | 非用户参数 |
| 启用反AI规则 | True | False 时输出保留套话 |

## 已知坑

瓶颈/关键路径是"高亮标红"的设计要求，节点不做任何流程分析（无工时计算），瓶颈在哪要用户自己判断后写进场景；回环流程只有"除非循环"一句例外口径，复杂回环需人工补规则。
