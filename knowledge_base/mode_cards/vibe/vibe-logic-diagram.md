## 意图

把复杂概念关系画成一张可读拓扑图时选它：规定节点/连线/关系类型/层级/防交叉五组设计规则。与"流水线图设计"的本质差别：表达概念间关系（含双向/反馈），不表达带时序的单向工序流。

## 核心手法

1. modes_design._build_logic_diagram_prompt：节点=概念（2-6 字），连线=关系，关系类型枚举 因果/包含/并列/递进/反馈。
2. 形状按类型统一（圆/方/菱形），颜色按分组；箭头方向=因果，线型实/虚=关系强度。
3. 层级自上而下或自左而右，主干+分支；节点间距均匀、连线不交叉。
4. 适配器传 style=扁平矢量、color_tone=_视觉调性（空则"高对比"）、count=4、逻辑主体槽=场景解析首个人物或物件（空则"逻辑待定"）。

## 参数表

| 参数 | 典型值 | 越界后果 |
|---|---|---|
| 核心数据包 | 含 _视觉调性 的 JSON | 空包时色彩基调落"高对比" |
| 逻辑主体 | 场景解析结果 | 空场景时显示"逻辑待定"，节点无内容源 |
| 数量 count | 4（适配器硬编码） | 非用户参数 |
| 启用反AI规则 | True | False 时输出保留套话 |

## 已知坑

关系类型（因果/包含/并列/递进/反馈）是固定枚举，超出五类的自定义关系无槽位表达；节点文案要靠场景文本携带，本节点不解析结构化概念列表。
