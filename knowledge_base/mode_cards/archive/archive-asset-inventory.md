## 意图

核对某输出目录已有什么文件时选它。与五个保存模式的本质差别: assets 恒为空 — 不写盘、不提交版本、不触发版本库写入, 是 10 模式中唯一直接面向磁盘目录而非版本库的只读模式。

## 核心手法

1. 目录扫描: build() 走 else 分支 assets=[], mode == "资产清单" 时 os.listdir(out_dir) 收 isfile 条目, 排除 .tmp 后缀, sorted 输出。
2. 目录来源透明: 报告首行标注 目录来源 (手动指定/默认) — 手动 输出目录 失败时显示 "手动目录不可用({e}), 已回退默认"。
3. 空目录诚实输出 "(空)"; listdir 异常静默按 0 文件处理。
4. 元数据槽仍完整 (项目/导演/模式/时间/输出目录/保存格式), 已保存文件 恒为空数组。

## 参数表

| 参数 | 典型值 | 越界后果 |
|---|---|---|
| 输出目录 | 空 | 空走 ComfyUI output → 插件 output 回退; 手动路径展开失败回退默认并在元数据"目录来源"标注 |
| 项目名 | 我的电影项目 | 决定打开哪个版本库 (元数据/打标); 与文件扫描无关 — 清单按目录全文件列出, 不按项目过滤 |
| 版本标签 + 目标版本 | 空 | 同时填写时对 目标版本(默认 head) 打标并写版本库 — 破坏"只读"预期, 不想改库就留空 |
| 核心数据包 | 空 | 只影响元数据的导演/场景字段与 AI 轨上下文 |

## 已知坑

- 清单按目录全文件列出 (含非本项目文件), 只过滤 .tmp; _versions 是目录不计入, 但散落在根目录的 .versions.json.gz 会计入。
- AI接口地址 有值时清单文本会送 LLM 重写 (结果 >200 字才采纳), 文件行可能被改写 — 想要逐字清单就别配 AI。
- 元数据槽"已保存文件"恒空数组是本模式的正常态, 不是故障。

## 节点映射

- 实现文件：aggregator/archive_master.py
- 分支/函数：build() else 分支 (assets=[]) + mode == "资产清单" 报告段 (os.listdir/isfile/.tmp 过滤) + 非保存模式打标段
- 数据来源：磁盘目录扫描; 版本库 aggregator/version_store.py :: open_store() (只读加载)。
