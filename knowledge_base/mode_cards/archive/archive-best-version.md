## 意图

多个版本里挑交付版时选它。与 版本对比 的差别: 输出是按评分降序的 top5 排行, 评分全部来自归档时写盘的真实数据 (资产数/字符数), 无人工打分入口。

## 核心手法

1. 评分排序: store.best(score_key="total", top_n=5) — 只收 scores.total 为数值的版本降序取前 5; total = 完整度×0.6 + 体量×0.4 (完整度=min(1, 资产数/5), 体量=min(1, 字符/40000))。
2. 权重含义: 5 类标准资产 (剧本/分镜/视频请求/手册/核心数据) 齐全得满完整度; 4 万字符 ≈ 120min 完整交付体量得满体量 — 完整度权重更高, 齐全小体量胜过单一大体量 (5 资产 8000 字 total 0.68 > 单资产 4 万字 0.52)。
3. 输出行: 排名 + name + id + total + 资产 kinds + 时间戳; 空库 → "(暂无带评分版本 — 请先执行 保存/版本提交)"。
4. 只读不提交; 与其他模式一样可顺带打标 (版本标签+目标版本)。

## 参数表

| 参数 | 典型值 | 越界后果 |
|---|---|---|
| 项目名 + 输出目录 | 我的项目 / 空 | 定位版本库; 换库名或目录即换排行, 跨项目对比需拼两个节点的输出 |
| 版本标签 + 目标版本 | 空 | 填写时给 目标版本(默认 head) 打标 — "给排行第一打 final"需手动填其 id, 打标目标不是自动取 top1 |
| 核心数据包 | 空 | 仅影响元数据; 评分与它无关 |

## 已知坑

- 评分只认 total 一个键: 手工往库里塞其他评分键不参与排序; scores 缺失的版本 (外部工具写入或旧库) 直接落榜。
- top_n=5 写死, 第 6 名起不可见; 需要全量清单走 版本历史 (含 total 但不排序)。
- 体量分母按"单版本全部资产字符和"计: 版本提交 截断到 200 万字符的资产仍会计满体量分 — 评分无法反映截断损失。

## 节点映射

- 实现文件：aggregator/archive_master.py
- 分支/函数：build() elif mode == "最优版本" (best top_n=5 渲染 + 空库提示); aggregator/version_store.py :: VersionStore.best() + compute_archive_scores() (0.6/0.4 权重常量)
- 数据来源：版本库 scores.total (来自真实归档 资产数/总字符)。
