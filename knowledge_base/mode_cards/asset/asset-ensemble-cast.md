## 意图

一个故事里有多条人物线、想一次建完整人物网络时选它。与单角色模式的本质差别：一次输出多张卡，每张带关系定位（与主角价值观对照等），且用户手填输入只作首卡，其余成员从核心场景解析。

## 核心手法

1. 人物网络装配：用户角色名（≠默认"主角"时）作首卡，再并入 scene_engine.parse_scene 解析出的角色并去重，截取前 5 人（cast[:5]）。
2. 首卡继承用户填的性格/外貌/服装；其余成员按"种子_人名_序号"从 _PERSONA_TRAITS/_LOOK_TRAITS/_WARD_TRAITS 独立补全，每人不同。
3. 关系定位种子池：非首卡从"与主角价值观对照 / 主角的情感软肋 / 推动关键转折 / 见证者/叙述者 / 暗线对手"5 选 1，md5 种子确定性。
4. 一致性策略行写明"每角色独立参考图锁定, 同框镜头用 IP-Adapter 多主体权重分配"，每张卡尾带按视觉风格+情绪的生成提示词行。

## 参数表

| 参数 | 典型值 | 越界后果 |
|---|---|---|
| 核心数据包 | Core 节点输出的 JSON 包 | 不接或场景描述为空→无从解析成员，cast 只剩用户一名，输出退化为 1 张卡的"群像" |
| 角色名 | 主角 | 留默认→首卡性格/外貌/服装也走补全池；改名→用户槽值优先作首卡并置于人物网络首位 |
| 视觉风格 | 写实 | 进每张卡的生成提示词行；选"🎲 随机"→系统随机 8 选 1，每次运行可能不同 |
| 参考图_角色正面 | IMAGE 或 STRING 路径 | 参考图计数写进一致性策略行；群像需每角色单独锁定，一张正面图不够覆盖全网络 |

## 已知坑

- 卡数上限 5 写死在 cast[:5]，而 parse_scene 返回的 characters 本身截前 3（aggregator/scene_engine.py :: parse_scene）——实际最多 4 张卡（1 用户 + 3 解析），"前 5"在当前管线达不到。
- 核心场景描述无人物词时 parse_scene 兜底返回 ["主角", "副线"]，群像卡会冒出这两个占位人名。
- 人物网络行只列 cast[:5] 名称，超出上限的解析角色被静默丢弃，无任何提示。
