## 意图

围绕单一主视点人物建卡时选它。与"角色设定"的差别：叙事定位写明"承载主题弧光, 从缺失走向完成"，且默认名"主角"时自动继承核心场景解析的首位角色——接了 Core 就不用重复填名字。

## 核心手法

1. 叙事定位取 `_CHAR_ROLE_HINT["主角角色"]`，卡头标注叙事视点定位。
2. 姓名继承：默认名"主角"且核心场景解析出角色→取首位（反派模式才取末位，本模式恒取首位）。
3. 缺槽确定性补全：性格/外貌走通用池，服装留空走 _WARD_TRAITS（无时代衣冠池）。
4. 道具绑定 + 三视图锚定块（正面/侧面/背面/表情 3 变体）+ 参考图计数一致性策略行。

## 参数表

| 参数 | 典型值 | 越界后果 |
|---|---|---|
| 角色名 | 主角 | 留默认且核心场景有人物→静默替换为解析首位；想自定名字必须显式填 |
| 角色服装 | "深蓝色工作服(褪色)..."（默认） | 留空→走 _WARD_TRAITS 种子补全；古风/未来等时代模式才走 _ERA_WARD |
| 核心数据包 | Core 输出 JSON 包 | 不接→无姓名继承、无道具绑定、导演风格固定"王家卫" |
| 参考图_角色正面 | IMAGE 或 STRING 路径 | 不接→一致性策略计 0 张；IMAGE 槽优先，落盘成功才回退 STRING |

## 已知坑

- 与"角色设定"共用同一分支和补全池，卡面骨架完全一致，差别仅在叙事定位文案与姓名继承方向——两模式同输入时输出高度相似（test_all_modes 唯一 hash 统计的是全节点逐模式，同节点内两模式仍可能撞近文）。
- 补全池种子含模式名与项目名：同故事换模式建卡会得到不同补全性格，跨模式人设不自动对齐。

## 节点映射

- 实现文件：aggregator/asset_master.py
- 分支/函数：build() `mode in _CHARACTER_MODES` 单角色子分支；姓名继承 `core_chars[0]`；`_CHAR_ROLE_HINT["主角角色"]`
- 数据来源：核心数据包→aggregator/scene_engine.py :: parse_scene（首位角色/物件）；参考图槽计数
