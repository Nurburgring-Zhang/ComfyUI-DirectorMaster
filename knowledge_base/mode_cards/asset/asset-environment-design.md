## 意图

为一场戏建空间总卡时选它。与 15 个环境细分模式的差别：设计指令取通用三层骨架（前景遮挡/中景动作区/后景信息层），适合尚未决定具体空间类型时的起步卡。

## 核心手法

1. 环境卡装配：环境类型（室内/室外/太空/水下/虚拟）+ 环境描述；描述留空时继承核心包场景描述，再退到 parse_scene 解析的地点词。
2. 设计指令块：`_ENV_DESIGN["环境设定"]` 三条编号输出——空间三层（前景遮挡/中景动作区/后景信息层）、光源单一可解释、留一处人物生活痕迹。
3. 场景内道具行：核心场景解析物件前 4 个（顿号连接），无物件则取 _关键道具 首段，再无则写"无"。
4. 环境锚定块：主色调按导演风格定、光影按情绪基调定、关键道具位置按场景描述定；一致性策略统计环境母版参考图数。

## 参数表

| 参数 | 典型值 | 越界后果 |
|---|---|---|
| 环境描述 | "厨房8平米, 灶台+砧板+碗柜+餐桌+窗"（默认） | 留空→继承核心包场景描述→parse_scene 地点词→全空时"环境描述"行输出空字符串 |
| 环境类型 | 室内 | 选"🎲 随机"→系统随机 5 选 1（室内/室外/太空/水下/虚拟），与设计指令文本无联动校验 |
| 核心数据包 | Core 输出 JSON 包 | 不接→无场景继承、无场景内道具行（写"无"）、导演固定"王家卫" |
| 参考图_环境母版 | IMAGE 或 STRING 路径 | 不接→一致性策略计 0 张环境母版，跨镜头空间/光影/色调只靠文本锚 |

## 已知坑

- 场景内道具行取 `core_objects[:4]`，parse_scene 返回 objects 截前 5——第 5 件之后被丢弃。
- 环境类型下拉与模式名（如选了"环境设定"类型却填"太空"）无一致性校验，类型与描述冲突原样输出。
