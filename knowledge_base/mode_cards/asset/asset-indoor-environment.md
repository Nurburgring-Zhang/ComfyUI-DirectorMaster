## 意图

厨房/卧室/办公室等封闭空间建卡时选它。与通用"环境设定"的差别：设计指令换成室内专属三条，围绕光路、居住年限暗示与墙面信息展开；类型槽默认"室内"与本模式天然对齐。

## 核心手法

1. 设计指令块输出 `_ENV_DESIGN["室内环境"]` 三条：窗户位置决定光路 / 家具磨损程度暗示居住年限 / 墙面物件交代人物背景。
2. 环境描述留空→继承核心包场景描述（室内词"厨房/客厅/卧室/办公室"命中 parse_scene 地点表）→地点词兜底。
3. 场景内道具行取核心物件前 4 个（顿号连接），环境锚定块按导演定主色/按情绪定光影。
4. 一致性策略统计环境母版参考图数，输出"跨镜头空间/光影/色调锁定"。

## 参数表

| 参数 | 典型值 | 越界后果 |
|---|---|---|
| 环境描述 | "厨房8平米, 灶台+砧板+碗柜+餐桌+窗"（默认） | 留空且无核心包→"环境描述"行输出空字符串，只剩设计指令撑卡 |
| 环境类型 | 室内 | 选"🎲 随机"→系统随机 5 选 1，可能抽到"太空"与本模式室内指令冲突 |
| 核心数据包 | Core 输出 JSON 包 | 不接→场景内道具行写"无"，地点行写"按场景描述" |
| 参考图_环境母版 | IMAGE 或 STRING 路径 | 不接→母版计数 0；室内空间透视最依赖母版，纯文本锚易跨镜漂移 |

## 已知坑

- parse_scene 地点词表按最长匹配，"厨房"命中后具体方位（灶台朝向）不进地点锚，只留在描述行——空间关系需用户在描述里自写。
- 设计指令与"环境设定"通用指令不同池：同场景在两模式间切换会得到不同指令块，下游按卡消费时注意模式统一。
