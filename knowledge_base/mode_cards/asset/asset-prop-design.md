## 意图

给有戏份的关键道具（信物/日记本/钥匙）建卡时选它。指令三条：道具可被演员真实操作、特写细节经得起放大、道具状态随情节演进。

## 核心手法

1. 设计指令块输出 `_PROP_DESIGN["道具设计"]` 三条（可操作/经得起放大/状态演进）。
2. 清单装配走服化道分支继承链——道具名写进服化道描述；留空→_关键道具+场景物件合并继承，这是本模式最常用的路径（核心包关键道具直达）。
3. 角色绑定行取核心角色前 3；生成提示词行按视觉风格+材质纹理+情绪组装。
4. 一致性策略统计道具母版参考图数，输出"跨镜头外观/材质锁定"。

## 参数表

| 参数 | 典型值 | 越界后果 |
|---|---|---|
| 服化道描述 | "旧信(泛黄), 钢笔(没墨水)"式清单 | 留空→靠核心包继承；两头都空→清单"未指定"+提示词占位"核心道具" |
| 核心数据包 | Core 输出 JSON 包 | _关键道具 首段还会被角色分支用作道具绑定；不接→继承链断 |
| 视觉风格 | 写实 | 进提示词行；"🎲 随机"→系统随机 8 选 1 |
| 参考图_道具母版 | IMAGE 或 STRING 路径 | 不接→母版计数 0；特写放大对参考图依赖度最高 |

## 已知坑

- 继承合并的去重是子串判断，"旧信"与"旧信(泛黄)"共存时两行都会出现。
- 道具状态演进（新→旧→损毁）需用户在描述里分段写清，卡面指令只提示原则不生成状态表。
