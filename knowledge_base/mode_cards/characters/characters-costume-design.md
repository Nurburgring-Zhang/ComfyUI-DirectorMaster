## 意图

做角色服装专项设计时选它。与服化道设定的差别收敛为 `_PROP_DESIGN["服装设计"]` 三条指令（服装是穿在身上的前史 / 主色辅色点缀色=60/30/10 / 磨损位置符合人物职业）；分支与继承机制完全共用。

## 核心手法

- 走 `else:` 服化道分支，卡落「服化道圣经」路。
- 设计指令块注入服装三条；60/30/10 配色比是提示词层规则，节点不校验用户描述是否符合该比例。
- 服化道描述清空时继承 _关键道具 + 场景物件前 4——注意继承源是「道具」不是服装语义，做服装专项时应手写服装清单。
- 角色绑定行取场景解析人物前 3 个；生成提示词固定追加「具体材质纹理」段。

## 参数表

| 参数 | 典型值 | 越界后果 |
|---|---|---|
| 节点模式 | 服装设计 | 非法值回退 角色设定 |
| 服化道描述 | （手写服装清单，如「洗旧工装, 帆布手套」） | 清空后继承到的是道具物件清单，可能全是「凤梨罐头」类非服装项 |
| 核心数据包 | 含 _关键道具 的 JSON 包 | 无角色时绑定行缺失；人物占位名问题同全体系 |
| 视觉风格 | 写实 | 逐字进提示词；不做服装-风格合理性校验 |

## 已知坑

- 继承源与模式语义错位：清空描述继承到的是道具/物件，服装专项务必手写清单。
- 与古风角色模式的 _ERA_WARD 无联动：本卡不产出角色穿着，角色着装要走角色类模式。
- 60/30/10 比例不校验，写在描述里的配色方案原样进卡。
- tests/test_all_modes.py 断言本模式执行非空；三视图锚定路输出占位句。
