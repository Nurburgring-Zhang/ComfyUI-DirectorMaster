## 意图

30-60 分钟直播的流程与话术设计：留人钩子前置、互动环节防流失、福利兑现承诺。与短视频族的差别：按直播时段（而非叙事结构）组织，"话术节点"是执行层核心标注。

## 核心手法

- `FORMAT_SCENE_SKELETONS["直播脚本"]`（script_studio.py:1111）6 槽：开播暖场·福利预告→内容带货段一→互动环节·弹幕福利→内容带货段二·高潮→福利兑现·互动峰值→下播预告收尾；45min 出 12 场，6 槽比例映射。
- 执行层直播分支（:1249-1252）逐场标注话术节点：痛点→演示→价格三段话术 / 故事引入→产品亮相 / 互动提问→福利钩子（seed 三选一）。
- 槽位 mission 硬约束："留人钩子前置""弹幕问答/抽奖/福利防流失""互动峰值兑现开播承诺""下次时间+内容预告"。
- `FORMAT_MODE_FLAVOR`（:932）：话术节点与节奏标注、留互动钩子防流失。

## 参数表

| 参数 | 典型值 | 越界后果 |
|---|---|---|
| 目标时长(分钟) | 0（自动→45） | 显式 30→8 场、60→15 场；≥110 归 120 桶（超出直播常态） |
| 对白密度 | 无(默认)→标准对白 | 直播全程口播——"零对白"档与直播形态根本冲突 |
| 节奏控制 | 无(默认)→中速 | "连续切镜(动作戏)"等剪辑类节奏对直播无意义；变速档对应上下半场节奏切换 |
| 核心数据包 | Core.核心数据包 | 商品/直播主题须写进场景描述；核心包缺失时"展示物"落占位物件 |

## 已知坑

- 12 场×6 槽映射后"内容带货段一"覆盖约 2 场——单款商品的完整话术要在场内展开，引用时按话术节点而非场数切。
- 直播间实时互动（弹幕/在线人数）不在任何参数内——脚本只给结构位与话术模板，动态应变靠场控。
