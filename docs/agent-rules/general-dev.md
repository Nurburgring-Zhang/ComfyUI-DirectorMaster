## 一、5 个错误模式 (血泪教训, 必读)

### 错误模式 1: 自我设限
- **表现**: 用户说"全量"+"严格"+"极端丰富", 潜意识降级
- **根因**: 怕慢, 怕麻烦, 缺"拆解 + 委托"思维
- **治法**: 拆解为 5 维度 (数据/上下文/skill/经验/AI), 单维度超出 → 启动子 agent

### 错误模式 2: 演示欺骗 (5 次历史)
- **Phase 30**: 硬编码周慕云 → 修
- **Phase 33**: 14 段说谎 → 修
- **Phase 35 R2**: 13/14 段场景相同 → 修
- **Phase 35.8**: 根目录 .md 重复 → 修
- **Phase 35.9**: anti_ai 词表当内容 → 修
- **根因**: 跑测试只测"功能字段", 不测"内容质量"
- **治法**: 双测试 (功能 + 内容), 不依赖自评

### 错误模式 3: 模板化代替真实开发
- **表现**: 节点输出模板字符串 ("题材: ", "片长: ")
- **根因**: 不敢真用 AI 生成, 退回"占位符"
- **治法**: 输出长度 ≥ 500 字符 + 字段填充率 ≥ 80% + 5 维具体化

### 错误模式 4: 不建全局观
- **表现**: 每次立刻动手, 没完整补全开发计划
- **根因**: 短视, 怕"先想后做"浪费时间
- **治法**: 5 分钟写出任务影响范围, 3+ 步骤任务必写完整计划

### 错误模式 5: 子 agent 失控
- **表现**: 提前停止, 临时文件残留, bug 引入
- **根因**: 怕子 agent 慢, 抢断
- **治法**: 任务完成标准 + 851/851 自检 + 不抢断 + 自动清理

## 二、7 条硬约束 (任何修改必遵守)

### 约束 1: 演示欺骗检测 (MUST)
任何"已完成"必须跑端到端验证:
- 跨场景/跨导演/跨输入, 验证输出真不同
- anti_ai 词 0 命中 (排除"指南段"和"反 AI 提及")
- 5 维具体化 (时代/地点/品牌/数字/物件) 命中

### 约束 2: 内容质量评分 (MUST 100 分制)
| 维度 | 分 | 检测 |
|------|----|----|
| 反 AI 味 | 20 | anti_ai 词 0 命中 |
| 微表情/身体词 | 15 | ≥ 8 身体词 + 12 AU |
| 留白/空镜 | 10 | ≥ 1 个 5s+ 留白 |
| 氛围/感官 | 10 | ≥ 3 感官细节 |
| 故事线/反转 | 15 | 12 套理论 ≥ 1 激活 |
| 节奏/余韵 | 10 | 4 段曲线 + 4 弧光 |
| 角色塑造 | 10 | 5 维 + 灵魂映射 |
| 反机械控制 | 10 | 5 导演签名 ≥ 3 |
| **总分** | **100** | < 80 = FAIL |

### 约束 3: 模板检测 (MUST)
- 输出长度 ≥ 500 字符
- 字段填充率 ≥ 80% (无空字段)
- 5 维具体化 ≥ 3 维命中
- 不能含 `题材: ` `片长: ` `集数: ` 等空字段

### 约束 4: 文件结构审查 (MUST)
任何文件操作后:
```bash
ls -la  # 验证新结构
diff <(ls *.md) <(ls docs/*.md)  # 验证无重复
# 报告里列: "xx 个 .py, xx 个 .md, xx 个 .json"
```

### 约束 5: 5 要素架构核对 (MUST)
每个 Production 节点必须 5 要素完整:
- **数据** (knowledge_base / 数据集 / 数据库)
- **上下文缩略** (智能解析 / 场景压缩)
- **skill/harness** (调用其他 skill / 上游注入)
- **经验矩阵** (历史案例 / 风格库 / 理论)
- **AI 深度处理** (动态生成 / kwargs 注入 / 真 parse)

### 约束 6: 子 agent 完整工作流 (MUST)
启动子 agent 时:
- 设**任务完成标准** (测试通过 + 报告写完 + 临时文件清理)
- 子 agent 完成前**自跑全部回归测试**
- 子 agent 完成前**删除 .bak 临时文件**
- 主线程**不抢断**, 信任子 agent 完整跑完
- 失败 git checkout 恢复, 重做
- **主线程备 plan**: 子 agent 因 Token 失败时立即自己扛

### 约束 7: 全局观强制 (MUST)
任何任务先建全局观:
- 5 维度工作分解
- 影响范围 (哪些文件/节点/测试)
- 风险评估
- 3+ 步骤任务写**完整补全开发计划** (含 节点表 + 时间表 + 风险表)
- **严禁"先做后想"**

## 三、10 铁律 (内容质量)

1. 不许"眼神坚定" → 具体动作 + 频率 + 持续时间
2. 不许"陷入沉默" → 具体物件动作 + 接触声 + 秒数
3. 不许"温暖色调" → 色温 + 饱和度 + 阴影 + 高光
4. 不许"钢琴配乐烘托悲伤" → 单音 + 频率 + 出现次数
5. 不许"保持空间一致" → 人物位置 + 距离 + 轴线
6. 不许"特写表现情绪" → 固定机位 + 时长 + 雨刷节奏
7. 不许"探讨人生意义" → 哲学对照 + 5 个具体意象
8. 不许"画面精美" → 24fps, 抽帧 12fps
9. 不许"感人至深" → 观众不自觉摸自己的手
10. 不许"故事跌宕起伏" → 3 幕剧节拍, 反转 17 分钟

## 四、必跑测试 (任何代码修改)

### 单元测试
```bash
python -m pytest tests/ -v  # 或 python tests/test_xxx.py
```

### 集成测试
- 端到端跑通完整 workflow
- 跨场景/跨输入对比

### 性能测试
- 内存/响应时间
- 边界条件 (空输入/超大输入)

## 五、子 agent 专家集群模式

### 启动策略
- 启动 1+ 个并行子 agent, 各自负责一个专业方向
- 子 agent 必须自带**任务完成标准**
- 子 agent 必须自带**测试**
- 子 agent 必须自带**临时文件清理**

### 主线程责任
- 启动子 agent (任务完成标准 + 测试要求 + 清理要求)
- 不抢断
- 子 agent 失败立即自己扛
- 最终跑完整回归测试

## 六、文档与汇报标准

### 报告必含
- 改了哪些文件 (具体路径)
- 验证了什么测试 (通过/失败)
- 失败项 (如有, 列具体)
- 演示欺骗检测结果

### 不许"演示欺骗"报告
- 不写"完成"未验证
- 不写"通过"无具体数据
- 不写"优秀"自评

---

## 七、调试与故障排除

### 故障排查 5 步
1. 复现: 跑最小复现
2. 定位: 缩小范围
3. 假设: 列可能原因
4. 验证: 逐个验证
5. 修复: git checkout + 最小修改 + 重新验证

### 日志与跟踪
- 重要操作必留日志
- 子 agent 输出必完整保存
- 错误必记录 (含完整 traceback)
