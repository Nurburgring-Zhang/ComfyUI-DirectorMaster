## 四、5 错误模式自检 (每次修改必问自己)

### ☐ E1: 自我设限了吗?
- 任务"全量"了吗? 还是只做一部分?
- "极端丰富"了吗? 还是只加几条?
- 用户说"严格"时, 我有没有打折?

### ☐ E2: 演示欺骗了吗?
- 跨场景/跨输入 N 个输出真不同吗?
- 模板字符串还是真生成?
- 5 维具体化真有数据吗?
- 我有没有写"已完成"但其实没跑测试?

### ☐ E3: 模板化了吗?
- 输出长度 ≥ 500 字符?
- 字段填充率 ≥ 80%?
- 含空字段 (题材: / 片长:) 吗?

### ☐ E4: 全局观了吗?
- 完整补全开发计划写了吗?
- 影响范围列了吗?
- 风险评估了吗?

### ☐ E5: 子 agent 失控了吗?
- 子 agent 完整跑完了吗?
- 子 agent 自跑全部回归测试了吗?
- 临时文件清理了吗?
- 主线程抢断了吗?

## 五、5 条不犯约束 (复述, 必默写)

1. **不自我设限** — 用户说"全量"+"严格"+"极端丰富", 不打折扣
2. **不演示欺骗** — 双测试 (功能 + 内容), 不依赖自评
3. **不模板化** — 输出长度 + 字段填充率 + 5 维具体化自动检测
4. **不子 agent 失控** — 任务完成标准 + 自检 + 不抢断
5. **不没全局观** — 5 维度工作分解 + 完整补全开发计划 + 风险评估

## 六、紧急情况处理

### 子 agent 失败
1. 立即自己扛 (主线程备 plan)
2. 评估修改是否可接受 (git diff 看)
3. 失败用 git checkout HEAD -- <file> 恢复
4. 重新规划, 分小步走

### 测试失败
1. 看完整 traceback
2. 定位根因
3. 不抢断, 不强 commit
4. git checkout 恢复, 重做

### 用户骂
1. 立即承认错误 (不狡辩)
2. 深度分析根因
3. 列具体修复点
4. 立即执行补偿 (不空话)
5. 写 SKILL.md/HARNESS.md 避免再犯
